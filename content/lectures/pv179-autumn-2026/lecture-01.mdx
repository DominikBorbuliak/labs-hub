# 3-Layered Architecture

This is the architecture we will use throughout this seminar.

<Spoiler label="Double click to reveal the 3-layered architecture">

```plain
┌────────────────────────────────────────┐
│           Presentation Layer           │  Controllers, Views, API endpoints
└────────────────────┬───────────────────┘
                     │ depends on
                     ▼
┌────────────────────────────────────────┐
│ Business Logic Layer / Business Layer  │  Services, business rules, validation
└────────────────────┬───────────────────┘
                     │ depends on
                     ▼
┌────────────────────────────────────────┐
│           Data Access Layer            │  Repositories, DbContext, entities
└────────────────────┬───────────────────┘
                     │
                     ▼
┌────────────────────────────────────────┐
│                Database                │  Actual data storage (e.g., SQL Server, SQLite)
└────────────────────────────────────────┘
```

- **Presentation Layer (PL)**: Handles user interaction — receives requests and returns responses (e.g., API controllers, MVC views)
- **Business Logic Layer / Business Layer (BLL/BL)**: Contains the application's core logic — validation, calculations, orchestration of operations
- **Data Access Layer (DAL)**: Responsible for communicating with the database — entities, `DbContext`, repositories
- **Database (DB)**: Where the data actually lives — only ever accessed through the Data Access Layer

A typical .NET solution structure for this architecture looks like this:

```plain
MyApp.sln
├── MyApp.Api          (ASP.NET Web API project — API controllers, Program.cs, appsettings, DI configuration)
├── MyApp.BL           (class library — services, interfaces, DTOs)
├── MyApp.DAL          (class library — DbContext, entities, repositories)
└── MyApp.Migrations   (class library — EF Core migrations)
```
